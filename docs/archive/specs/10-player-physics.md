## 0. 校准原则

**REQ-PHYS-100**: 本项目复刻对象为 **SMM2**。凡 SMM2 与原原作（SMB1/SMB3/SMW）行为不一致处（如 SMM2 内置的拐角纠偏），**以 SMM2 实测数据为准**，原作反汇编数据仅作对照参考。每项机制标注其来源：`SMM2 原生` / `现代辅助（本项目内置）`。

**REQ-PHYS-100a**: 三项手感辅助（土狼时间、跳跃缓冲、拐角纠偏）为**常开内置行为，不提供配置开关**。

## 1. 核心手感算法

**REQ-PHYS-101 变高跳跃（双重力机制）** `SMM2 行为的工程近似`
跳跃高度通过双重力实现：上升阶段且仍按住本次起跳的 `jump`/`spin_jump` 时应用 `gravity_rise`；松开后锁存为短跳，不允许再次按键恢复低重力；下落应用 `gravity_fall`。禁止使用松开按键乘速度系数的简化实现。两项重力均为 CANDIDATE；公开逐帧轨迹提示更复杂的上升变化，不能声称本算法就是 Nintendo 内部实现。

**REQ-PHYS-102 土狼时间 (Coyote Time)** `现代辅助`
离开平台边缘后的 N 物理帧内仍允许起跳。N 来自 Profile，属于项目辅助设计。落地重置窗口；离地当帧计为第 1 帧；起跳或超时立即失效，主动跳跃后不可利用旧窗口再次跳跃。

**REQ-PHYS-103 跳跃输入缓冲 (Jump Buffering)** `现代辅助`
按下跳跃当帧计为缓冲第 1 帧；M 来自 Profile，属于项目辅助设计。窗口内着地时设置起跳速度，下一物理步移离地面。记录普通/旋转类型及实际按键，不可叠加多次按压；变身定格期间窗口停止老化。起跳或超时清除。

**REQ-PHYS-104 拐角纠偏 (Corner Correction)** `工程辅助，SMM2 精确阈值待测`
仅在向上运动且预测命中天花板时检查左右最近空隙，先检查平移全程，再检查平移后的本帧运动；最大距离来自 Profile。水平墙碰撞不得触发上方纠偏。两侧均不可通过时正常顶头；成功纠偏保持水平速度。

**REQ-PHYS-105 顶块交互与防黏连** `工程实现`
头部撞击且碰撞法线 `normal.y > 0.5` 时：对被撞击方块触发 `hit_by_player()`（携带玩家状态与撞击方向），随后将玩家垂直速度重置为 Profile 的 `head_bump_speed`（CANDIDATE），防止与方块底面黏连。一帧内撞击多方块时只对水平重叠最大的一个触发交互。

## 2. 地面与滑行

**REQ-PHYS-106**: 松开方向键时的地面自然减速使用 Profile 的 `friction_normal`；反向输入时使用 `skid_decel`。当前水平速度达到 `skid_threshold` 且方向相反时进入滑行状态（播放滑行动画与音效）。进入后，即使速度降至触发阈值以下，也持续使用刹车阻尼和滑行动画，直到松开反向输入、离地、速度归零或反向完成。参数值及校准状态统一定义于 `01-physics-profiles.md`；现有 `skid_decel` 经试玩反馈力度不足，需重新测量，禁止标记 TUNED。

**REQ-PHYS-107 — DEPRECATED（2026-09-29，由 REQ-PHYS-113 替代）**: 达到 `run_max` 后维持按住 `run` 可保持极速；当前风格能力开关 `p_meter` 开启时（REQ-PHYS-005），地面满速持续奔跑每帧蓄积 `p_meter_charge_per_frame`，满 `p_meter_max` 后速度上限切换为 `p_speed`，普通跳跃改用 `super_jump_initial`，并在当前 SpriteFrames 含 `p_jump` 时使用该上升姿态。地面未满足蓄积条件时每帧扣除 `p_meter_decay_per_frame`；空中保持原方向输入且未撞墙时冻结，否则按该值衰减。刹车、下蹲、撞墙、受伤、进门/管道时清零。`p_meter` 关闭的风格保持 0。112/+2/-1 是 `CANDIDATE`，不是 TUNED；进门/管道事件的连接归相应交互系统任务。

**REQ-PHYS-109 移动状态与逐帧顺序**: Player 显式暴露互斥的 `IDLE`、`RUN`、`AIR`、`CROUCH`、`SKID`、`DEAD` 移动状态，并在状态转换时发信号；旋转跳是 `AIR` 中的跳跃类型，不复用变身状态机。每物理帧按“读取逻辑 Action 与缓冲 → 更新碰撞盒及水平速度 → 消费合法跳跃 → 应用双重力 → 拐角纠偏 → `move_and_slide()` 一次 → 处理顶块及落地缓冲 → 发布状态与动画”的顺序运行。`PowerUpManager` 的形态状态独立于移动状态，遵循 `11-player-statemachine.md`。

**REQ-PHYS-110 速度驱动移动动画**: 行走/跑步帧数按实际水平位移推进，相位连续累积；每移动 `animation_stride` 像素推进一帧，静止不推进。走/跑姿态切换不每帧调用 play 或重置相位。全部帧更新运行在 60Hz 物理步，不让 AnimatedSprite2D 再按渲染时间自动推进。stride 是工程候选，待原始帧表校准。

**REQ-PHYS-111 下蹲跳姿态**: SMB1、SMB3、SMW 的小型形态均可下蹲，遵循项目负责人对 SMM2 的直接试玩观察；Gemini 报告中“小型 SMB1/SMB3 不可下蹲”混入旧作规则，已驳回。本地拆包目录 `TBDtoVERIFIED/textures/styles/{smb1,smb3,smw}/player/` 均有 `mario_small_duck_Strip1.png`，各为 16×32 单帧；工程 SMW `small/duck.png` 与 SMW 拆包帧像素一致。下蹲时起跳后保持下蹲姿态至落地，即使空中松开下方向也不立即切回普通跳跃姿态。移动状态仍为 `AIR`。小型下蹲地形盒/受击盒尚无 SMM2 可复查数值；工程预览暂保留站立地形盒，不声称其为已验证的下蹲尺寸。SMB1/SMB3 风格贴图尚未接入游戏场景。

**REQ-PHYS-112 走路到跑步姿势切换**: 依据负责人 2026-09-29 实际观察，只有达到 `run_max` 才使用 run 帧条；不使用 walk_max 阈值、蓄积满表或额外确认延迟。普通满速起跳锁存 `p_jump`，从起跳到落地保持该贴图，空中减速、松开 run、越过顶点均不改成 jump/fall。下蹲跳/旋转跳保持各自姿态优先级。当前 SMW small 的 run 映射至 `mario_small_run_Strip2.png`；不凭文件名推断第三种独立跑姿。

**REQ-PHYS-113 最高跑速与速度驱动跳跃**: 常规地面最高速度为 run_max，没有 P-Meter 解锁的第三档。普通跳跃初速按起跳瞬间 abs(vx) 在 walk_max→run_max 范围内插值 jump_initial→run_jump_initial；满速跳姿按 REQ-PHYS-112 锁存。候选 P-Meter 独立保留用于调试对照和未来飞行状态；任何容量/蓄衰值不得改变本条跑速、跑姿或跳高。

**REQ-PHYS-114 空中动量**: 不输入方向时保持水平动量。相同方向输入且速度已高于当前输入的行走上限时，不向较低上限强制减速；反向输入按空中加速度刹停后再加速。释放跳跃后即使重新按住也不恢复长跳重力。

**REQ-PHYS-115 组件与碰撞边界**: 输入快照、运动模型、碰撞形状/查询、动画相位、PowerUpManager、搬运分别实现；Player 只负责编排与 Godot 运动求解。移除旧 State/StateMachine，不保留兼容访问器。地形主体只与 solids/semisolids 求解；敌人通过 Area 事件队列与独立 Hurtbox 交互，同一接触先判断踩踏后受伤，避免回调顺序改变结果。形态/伤害事件在下一安全物理帧处理，禁止在 Area 回调中直接改 shape。

**REQ-PHYS-116 仪表盘校准**: 调参使用实例独立 Profile；暂停/单帧、复位、形态/风格能力、刹车候选对照、受击与搬运探针均可操作。记录逐帧输入/位置/速度/状态/动画、起跳高度及滞空帧数、静止加速到满速帧数、反向刹停帧数和距离。可导出 Profile、CSV 与来源元数据至 user://；不得自动修改仓库基线或自动签认 TUNED。

**REQ-PHYS-117 移动状态所有权**: `PlayerMovementStateMachine` 独立持有只读状态；运动模型提供接地、蹲姿、刹车与求解速度，状态机按 AIR → CROUCH → SKID → RUN → IDLE 的优先级解析存活状态，起跳可提前进入 AIR。死亡只能通过专用入口进入 DEAD；DEAD 忽略普通解析、起跳和弹跳，只有显式复位能够退出。每次实际转换先提交新状态，再依次发出退出、进入、转换信号；死亡不经过用于复位的 AIR。输入、速度积分、碰撞求解和动画不放入状态机，不允许外部写状态或直接调用旧状态节点。

**REQ-PHYS-118 — DEPRECATED（2026-09-30，由 REQ-PHYS-120 替代）**: 玩家 Sound 子节点中的效果音按单次事件播放，实例化时复制音频流并禁用 WAV/Ogg/MP3 循环标记。进入 SKID 时只触发一次刹车音效；退出 SKID、进入变身演出或复位时停止刹车声。复位清理仍在播放的玩家效果音，避免上一轮声音残留。运行时设置不得改写共享素材或依赖仅存在于本机的导入标记。

**REQ-PHYS-119 可重复试玩入口**: 仪表盘提供平地跑跳、平台边缘（土狼窗口）、空中落地（跳跃缓冲）、天花板擦角、16px 狭缝及现有方块/敌人交互的入口选择；复位回到所选入口并清理上一轮计量。空中与擦角入口可默认暂停，保留既有单帧操作。场地几何和入口位置来自 data/debug 配置，属于调试场地设计，不作为 SMM2 实测参数。导出记录包含入口 ID、记录起始 Profile 及参数变更的绝对样本索引，禁止用滚动缓存长度作为时间位置。

**REQ-PHYS-120 状态音效与音量**: 玩家音效和主场景 BGM 使用无位置的 AudioStreamPlayer，不随玩家/相机离开世界原点而衰减。刹车声复制实例流并启用正向循环，仅在 ACTIVE 的 SKID 运动状态持续播放；退出刹车、演出定格、死亡或复位时停止，演出后仍处于 SKID 则恢复。循环不得每帧重新从头启动，其他事件音保持单次播放；不改写共享媒体资源。暂停遵循场景暂停状态。

## 3. 验收标准（M1）

**REQ-PHYS-108 数值仪表盘调试场景**
M1 验收前必须交付 `res://src/gameplay/debug/physics_dashboard.tscn`：可自由跑跳的测试场景，HUD 实时显示 `velocity`、`position`、P-Meter、当前状态机状态，并可绘制最近 5 秒速度曲线。

验收清单：
1. 仪表盘实测：走/跑极速与 Profile 一致；P-Meter 不改变极速/跳高/姿势（REQ-PHYS-113）；
2. 短按/长按跳跃高度比与双重力参数的理论曲线吻合；
3. 土狼窗口边界逐帧验证：窗口内可跳、窗口外第一帧不可跳；
4. 缓冲窗口边界逐帧验证：窗口内落地自动起跳、窗口外失败；
5. 纠偏阈值边界验证：阈值内擦角通过不卡头、阈值外正常顶头；
6. 顶问号块触发弹出动画且玩家不黏连；
7. 项目负责人试玩签认手感。
