## Native behavior

The existing left-panel theme button opens its native EditorPopout. Ground,
Underground, Underwater, Ghost House, Airship and Castle buttons immediately
refresh the background, native ground/start-ground, slope art, relevant static
previews, palette/cards and edit music. A selection closes the panel and is one
UndoRedo action. Existing positions, contents, variants and independent terrain
Parts remain authored objects. Choosing the current theme makes no new action.
The picker rejects runtime/held-object/save-in-progress changes.

The user subsequently requested the SMM2 menu presentation, while keeping the
six-theme content scope. The actual Course Maker screenshot in
[this theme guide](https://www.shacknews.com/article/112708/every-course-theme-in-super-mario-maker-2-course-maker)
shows two columns of landscape cards. The port now uses those proportions and
the project's existing ButtonHoverEffect for red selection/hover corners. The
user explicitly rejected reimplementing that effect and requested no name labels;
there are no card labels/tooltips or custom corner-drawing code. Four additional
SMM2-only themes and the day/night control remain outside the selected scope.

SubArea replaces only environment nodes; it preserves Parts and existing level
signals. EditorPlayer and goal sprites are not loaded a second time. Play uses
the chosen theme's music, then editing restores its editor music/offset. SWE
already has the required ground/ghost aliases; both signed wrappers retain the
selected theme and unknown fields. Unsupported legacy theme/style metadata is
preserved; only the six SMW day choices are advertised by this picker.

## Source and assets

Read-only ../openwe-ref reference:

- obj_bg1/Mouse_4 and Other_10: editor selection, theme music and new liquid.
- scr_tiles_ground: spr_ground /2 /3 /4 /5 /6 for ground/underground/castle/
  underwater/ghost/airship. Native GodotWE's53-choice topology is authoritative.

  underwater/ghost frame lists (ghost1/2/3/2). obj_bganimator/Alarm_0 uses ten

- scr_snd_* and scr_snd_editor_*: source per-theme edit/play music; original
  GodotWE overworld streams are retained. Ogg music loops through MusicPlayer.

smw_themes.json owns theme content; smw_ground_frames.json separately maps raw
source roles to native atlas coordinates. GroundPart.atlas_for is unchanged.
Do not use LevelProcessor.SWE_GROUND_FRAME_TABLE as raw sprite order: from43
onward the contracts differ. scr_auto_tile's raw43 is filled material,44 isolated,
45 vertical strip and46 horizontal strip. Native decorative choices share the
corresponding ordinary source edge/body. The same basic mapping applies to all
five non-overworld themes; spr_ground2's extra50+ frames include diagonal assets,
not native square-edge decorations. The adapter starts transparent rather than
retaining unfilled grass slots. The overworld atlas remains the original resource.
Ground/start/slope cache keys include the chosen atlas. Source sprites are copied
under ignored assets/openwe only.

Complete paired standalone/filled slope assets are still unavailable outside
overworld, although underground contains some diagonal pieces. The earlier blanket
claim that all source sheets have no diagonal art was incorrect. A fallback derives
theme surfaces from top21/body43/bottom27; it is temporary, not original SMM2 art.
Optional PNGs now work for steep16x32 and gentle32x32 slopes, both directions and
standalone/filled versions, under textures/tiles/slopes/{overworld,underground,
underwater,ghost,airship,castle}/. Existing root gentle paths remain overworld
aliases. The README lists exact missing groups, size/alpha/geometry contracts.
Non-overworld steep and gentle palette previews now follow the selected atlas.

Background child nodes now get WorldPresentation's display camera correction,
including the pre-existing overworld CanvasLayer child. Foreground and scenery
therefore share interpolation. Source image pixels and physics are not changed.

The first GPU check exposed a real bug: old ground-only SWE fixtures contain
unused water_level0. Carrying that value into a new castle placed lava near the
room ceiling and tinted the entire view. Source selection creates a fresh
surface at room_height-4, so entering a liquid theme now sets native start/limit
to-16 (surface root-4). Undo/redo stores/restores theme AND all three liquid
settings. Loading an existing saved castle keeps its authored values.
