# SMW swimming — selected continuation, 2026-10-23

The user selected SMW swimming now after six-theme switching. This completes
the ordinary underwater player path, without adding another game style or
new theme selector. Earlier theme-only acceptance explicitly excluded swimming;
this record supersedes that exclusion for the selected SMW player slice.

## Source contracts

Read-only reference: OpenWE `2f84414054c576bf7ca03dfa33b244ee730d57da`.
`obj_mario/Other_13` separates empty-hand strokes from held-item buoyancy;
`Step_2` selects stroke/float/held poses; `Other_11` supplies water stomp
rebound; `Step_0` and the end of `Other_13` define water entry/exit and room top.
`scr_swim` selects SMW's `snd_swim`. `Alarm_9`/Create plus `obj_bubble` and
`pth_bubbles` define the separate sprite effect, path and emission clocks.

Native units are pixels/second, at60Hz. Source velocities multiply by60 and
accelerations by3600. `PlayerSwimRules` centralizes these constants:

| Behaviour | Native value |
|---|---|
| Horizontal acceleration/deceleration |180px/s²|
| Airborne water horizontal cap |60px/s, independent of Run and star speed|
| Submerged floor cap |30px/s|
| Empty-hand gravity |108px/s²|
| Pre-stroke sink/rise caps |60/-90px/s|
| Jump press while sinking |Reverse vertical speed, then subtract10.8px/s|
| Jump press while rising |Subtract36px/s|
| Jump press on submerged floor |-60px/s|
| Held buoyancy |Subtract1800px/s², pre-input rise cap-60px/s|
| Held idle drift |Facing direction, up to30px/s|
| Held Down |Reverse rising velocity plus10.8, or add36 while sinking|
| Water enemy rebound |-100.5px/s, retain swimming state|
| Held-Jump surface exit |-247.5px/s through native variable-jump state|

Source clamps **before** applying input and gravity. It intentionally permits
a one-tick impulse beyond a steady cap, including held diving up to97.8px/s.
Gravity runs once after the state. Held Jump does not repeat strokes; Spin
does not become an underwater spin jump. Water floor movement retains native
SMW crouching, look-up and walking poses, without running skid/P-meter logic.

Full underwater themes are water everywhere. The existing partial-water
runtime uses source feet-space hysteresis: enter at feet>=surface+14; exit at
feet<=surface+12. Lava/poison cannot activate swimming. Holding Jump on exit
uses the existing jump's variable-height gravity; releasing it restores normal
gravity. This uses existing surface infrastructure for verification and does
not expose forest/beach/night themes in the six-theme UI.

## Native ownership and rendering

`PlayerSwimmingState` reuses the existing player collider, movement, powerups,
held-item ownership and collision signals. It handles small, Super and Fire
Mario with unedited `spr_mario_{small,big,fire}_swim` and `_swim_hold` art.
Strokes show the three source frames at9fps, then loop the separate float
sprite. Held rising pins frame0; held falling animates at9.6fps. Origins keep
the existing source y+1 convention. Fire input/poses use the normal FirePowerup.

The environment resolver cannot override goal, death, frozen, stunned, note
or spring compression states. Ordinary states resume swimming on the next
physics tick where appropriate. Water rebound retains its own controller,
while existing enemy stomp signals still create normal rewards/effects.

Picking up an object within a continuous state now places it at the existing
native hand offset **after deferred reparenting**. It no longer depends on
entering a new locomotion state. This shares the same release/drop path as
land controls, and is covered by the existing regression suite too.

`PlayerBubble` follows the original piecewise path at60px/s with6fps art and
0.8alpha, pops at solids/surface and uses area-owned deferred spawning.
WorldPresentation interpolates it alongside Mario. Editor return/retry removes
all runtime bubbles and pending actors; no user/source sprite pixels change.

## Verification

`player_swim_test` uses independent explicit source constants, a saved/reopened
native underwater course and actual physics bodies. It checks sink/stroke
timing, all three stroke frames, held-button semantics, Run/Spin limits,
wall/ceiling collisions, a real question-block head bump, ground crouching,
held-object pickup/hand position/buoyancy/dive/release, actual enemy rebound,
water entry/exit, the underwater room top, fire shooting, damage, freeze/thaw,
bubble path/solid pop, death and edit/replay cleanup.

`capture_slice.py --player-swim --fps 60/120` runs the same fixture through
real OpenGL. Frame-pre-draw samples the displayed transform after presentation;
post-draw checks actual pixels against original source frames and origins.
The oracle includes mirrored poses, waits for the native entry fade, and
excludes screen UI and the covered pixels of actual foreground
objects/bubbles/thaw effects, including shadows. Surface-water overlay samples
are separate from the full-underwater raw-art comparison. It never permits a
nonzero mismatch among the remaining sampled pixels. Captures include small
sink/move, Super/Fire stroke/float, crouch, held rise/dive and fire shooting.

Final fresh import, five metadata checks and all56 registered native scenes
pass. Actual GL60/120 passes5752/5752 and11595/11595 unobscured source pixels.
Matching captures/logs retain_60/_120 suffixes; full report/artifact details
are in HANDOFF.md. Other game styles, Yoshi/mounts, frog/penguin
powers, night physics and future warp travel remain outside this selected slice.

The first full aggregate found four old-fixture assumptions: contact tests
used land-speed descent and insufficient water contact windows; plant tests
expected a forced air spin pose to survive underwater; a shot-only splash
counter included Mario's newly implemented entry splash. The corrected tests
retain their real collision/damage/reward assertions and isolate unrelated
Mario motion only in that projectile-only oracle. The five affected native
scenes pass focused reruns. Source/GPU comparisons also distinguish intentional
front-layer occlusion, mirroring and the entry fade from gameplay sprite art.
